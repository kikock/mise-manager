## 1. 核心数据结构与配置模型

### 1.1 应用运行时配置契约 (`config.json`)

配置文件持久化存储于 `%APPDATA%\mise-manager\config.json`：

```typescript
export interface AppConfig {
  miseRootDir?: string;    // 用户自定义的统一根目录 (默认 [AppBaseDir]\mise)
  miseDataDir?: string;    // 数据存储目录 (默认 [miseRootDir]\data)
  miseBinDir?: string;     // 垫片 shims 目录 (默认 [miseDataDir]\shims)
  miseBinPath?: string;    // 手动指定的外部 mise.exe 绝对路径
  proxy?: string;          // 自定义网络代理地址 (如 http://127.0.0.1:7890)
  theme?: 'dark' | 'light' | 'system'; // 用户首选界面主题
}
```

### 1.2 市场缓存结构模型 (`market_cache.json`)

持久化存储于 `%APPDATA%\mise-manager\market_cache.json`：

```typescript
export interface MarketCacheData {
  cachedAt: number;        // 缓存创建时间戳 (毫秒)
  tools: ToolSummary[];    // 官方 1000+ 工具元数据清单
  downloads: Record<string, number>; // 各工具下载热度统计字典
}

export interface ToolSummary {
  name: string;            // 工具标识符 (如 "node", "python", "go")
  description?: string;    // 工具用途详细描述
  homepage?: string;       // 官方主页或开源代码仓库 URL
  category?: string;       // 分类标签 (如 "languages", "cli", "backend")
}
```

### 1.3 已安装工具与版本聚类模型 (`InstalledToolGroup`)

主进程向渲染进程返回的已安装工具聚合结构：

```typescript
export interface InstalledToolGroup {
  name: string;                   // 工具名称 (如 "node")
  activeVersion: string | null;   // 当前激活版本 (如 "20.18.0")
  versions: InstalledVersion[];   // 该工具下所有物理安装的版本列表
}

export interface InstalledVersion {
  version: string;                // 版本号标识 (如 "18.20.4")
  installPath: string;            // 本地绝对物理存储路径
  installed: boolean;             // 是否物理完整安装
  active: boolean;                // 是否为当前激活状态
  source: string | null;          // 激活来源 (如 "C:\Users\ck\.config\mise\config.toml")
  requestedVersion: string | null;// 请求版本规格 (如 "20")
}
```

## 2. 核心算法与底层关键实现

### 2.1 毫秒级运行时状态缓存算法 (`main.js` -> `mise:check`)

为了杜绝每次界面切换频繁调用子进程引发的性能抖动，主进程引入基于文件修改时间戳（`mtimeMs`）与文件字节体积（`size`）的内存缓存：

```javascript
let miseCheckMemoryCache = null;

ipcMain.handle('mise:check', async (event, forceRefresh = false) => {
  const miseExe = getMiseBinPath();

  // 若非强制刷新，且目标 exe 状态与内存快照一致，直接返回缓存结果 (耗时 < 1ms)
  if (!forceRefresh && miseCheckMemoryCache && fs.existsSync(miseExe)) {
    try {
      const stat = fs.statSync(miseExe);
      if (stat.mtimeMs === miseCheckMemoryCache.mtimeMs && stat.size === miseCheckMemoryCache.size) {
        return miseCheckMemoryCache.data;
      }
    } catch (e) {}
  }

  // 设定 2.5 秒全局安全兜底超时，防止进程假死
  return new Promise((resolve) => {
    // ... 执行 execFile(miseExe, ['--version'], { timeout: 1800 })
    // 成功后缓存文件特征与结果数据：
    miseCheckMemoryCache = {
      mtimeMs: stat.mtimeMs,
      size: stat.size,
      data: resultData
    };
    resolve(resultData);
  });
});
```

### 2.2 双轨互补工具扫描与降级算法 (`mise:listInstalled`)

当用户安装了大量工具或某些工具损坏时，CLI 命令可能出现超时，系统通过双轨机制实现绝对可靠性：
1. **主轨道 (CLI 快速探测)**：执行 `mise ls --installed --json`（超时设为 2.8 秒）；
2. **辅轨道 (物理目录扫描 `installs/`)**：
   - 遍历 `miseDataDir/installs/` 目录；
   - 枚举子目录获取工具名与物理版本号；
   - 快速合并补充至输出字典；
3. **降级保障**：若主轨道超时或报错，辅轨道扫描算法立即在 3.0 秒内强制收口返回，保证界面绝对不会出现永久旋转加载状态。

### 2.3 PowerShell UTF-16LE 脚本原子注入机制

在 Windows 下直接执行命令行参数极易因反斜杠 `\`、空格或单双引号引发转义解析错误。系统统一采用 Base64 编码的 UTF-16LE 脚本传递给 PowerShell：

```javascript
function runPowerShellScript(scriptText) {
  return new Promise((resolve) => {
    const b64 = Buffer.from(scriptText, 'utf16le').toString('base64');
    exec(`powershell -NoProfile -EncodedCommand ${b64}`, (err, stdout, stderr) => {
      if (err) resolve({ success: false, error: stderr || err.message });
      else resolve({ success: true, output: (stdout || '').trim() });
    });
  });
}
```

### 2.4 PowerShell Profile 自动化接入与告警抑制清洗

自动识别 PowerShell 5.1 与 PowerShell 7 路径，并使用正则精确注入/清理：

```powershell
# 注入的代码块模板：
# >>> mise initialize >>>
$env:MISE_PWSH_CHPWD_WARNING = '0'
if (Get-Command mise -ErrorAction SilentlyContinue) {
    mise activate pwsh | Out-String | Invoke-Expression
}
# <<< mise initialize <<<
```

- **清洗算法**：通过正则表达式 `(?ms)# >>> mise initialize >>>.*?# <<< mise initialize <<<` 与单独的激活语句正则，实现无残留的纯净清理与幂等注入。

### 2.5 零延迟 Windows 原生外部程序唤起

在 Windows 平台下，使用 Electron 自带的 `shell.openExternal` 可能会因 DDE 协商超时引起数秒卡顿。主进程针对 Windows 进行了专用优化：

```javascript
ipcMain.handle('shell:openExternal', async (event, url) => {
  // Windows 平台使用 cmd.exe /c start "" 异步分离子进程，毫秒级快速唤起外部浏览器
  if (process.platform === 'win32' && /^https?:\/\//i.test(url)) {
    const child = spawn('cmd.exe', ['/c', 'start', '', url], {
      detached: true,
      stdio: 'ignore',
      windowsHide: true,
    });
    child.unref();
    return true;
  }
  return shell.openExternal(url);
});
```

## 4. 容错与恢复策略

| 异常现象 | 诱因剖析 | 处置与恢复预案 |
| --- | --- | --- |
| **GitHub API 限流 (403)** | 短期内频繁触发检查更新 | 内存中对 Releases 实施 10 分钟强缓存；检测失败时优雅降级并展示备用 GitHub 网页链接。 |
| **第三方安装包编译失败** | 缺少对应语言的编译环境 | 子进程实时推送全部错误日志至流式窗口，安装失败捕获非零退出码，保持界面可用并允许用户复制完整错误堆栈。 |
| **PowerShell 执行策略受限** | 机器配置了 Strict 执行策略 | 脚本执行统一前置 `-ExecutionPolicy Bypass -NoProfile` 参数，保证系统免授权平滑执行。 |
| **杀毒软件拦截子进程** | 无证书签名被误报 | 关键安装向导提供 FAQ 提示用户勾选“仍要运行”，并支持纯便携绿色免安装模式。 |
