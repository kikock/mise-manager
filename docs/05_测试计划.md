| 项目 | 内容 |

| 测试环境 | Windows 10 x64 / Windows 11 x64（覆盖实机与纯净沙盒环境） |

## 1. 测试策略与质量目标

### 1.1 总体测试策略
针对 Mise Manager 涉及底层系统环境变量、PowerShell 脚本执行与流式子进程管道的特性，构建全流程测试矩阵：
1. **主进程 IPC 单元与接口测试**：验证配置读写、文件探测、Base64 脚本编码逻辑；
2. **系统环境变量与注册表集成测试**：在隔离沙箱中测试环境变量原子写入、老路径清洗、Profile 注入与幂等性；
3. **市场数据与离线缓存测试**：验证分页拉取容错、6 小时离线 JSON 缓存生命周期、关键字模糊匹配；
4. **自动化回归与页面视觉测试**：依托内置的 `yarn screenshot`（`electron . --screenshot`）进行全页面自动化高保真渲染比对。

### 1.2 质量准出基线
- **P0 级核心业务用例通过率**：100%（环境变量不可损坏，安装进程可控中断）；
- **环境原子性要求**：环境变量写入与清理测试连续执行 20 次，用户 `Path` 长度与条目严格受控，无重复或丢失已有系统项；
- **冷启动指标**：启动无白屏停顿，首屏呈现时间 ≤ **1.2 秒**。

## 3. 混沌与极限场景测试 (Stress & Chaos)

1. **极端弱网与 API 阻断**：
   - 模拟 GitHub API 触发 403 限流或 404，验证应用是否依然平滑运行，展示备用下载链接且不报错；
2. **磁盘空间耗尽测试**：
   - 当安装大型工具（如带有复杂编译环境的 SDK）遇到磁盘写满时，系统能捕获流式错误退出，杜绝死循环卡死；
3. **高频快速切换测试**：
   - 在应用市场、已安装、设置页面之间以每秒 5 次的频率快速连续切换，验证内存无泄漏、DOM 无残留、无事件重复监听。

## 4. 自动化回归测试流水线 (`yarn screenshot`)

项目内置了自动化无头运行与截屏验证通道：
- **执行命令**：`yarn screenshot`（即 `electron . --screenshot`）；
- **执行流程**：应用静默启动后，自动化脚本依次导航访问首页、应用市场、已安装工具、系统设置、历史版本模态框、浅色主题首页，自动捕获各页面高保真渲染图并存入 `docs/screenshots/`；
- **断言标准**：6 张截图尺寸全部为 1240×820，文件大小完整，无渲染黑屏或字体缺失。

## 5. 缺陷等级评定与退出准则

| 等级 | 判定标准 | 处理要求 |
| --- | --- | --- |
| **P0 (阻断)** | 写入导致 Windows 系统原有 Path 丢失、卸载导致非关联目录被删、程序主流程崩溃 | 立即阻断发布，当日修复并回归 |
| **P1 (严重)** | 工具版本无法安装、市场离线缓存解析失败、中止进程无法杀灭 | 24 小时内修复完成 |
| **P2 (一般)** | 某些非主流语言版本识别缺失、界面个别文案换行微偏 | 纳入常规迭代排期 |
