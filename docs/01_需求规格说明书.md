## 1. 引言

### 1.1 编写目的
本文档详细定义 **Mise Manager** 桌面端产品的业务定位、功能架构、性能与安全非功能需求，明确系统各项业务规则与边界约束。本文档作为后续版本迭代（如多环境配置方案隔离、离线离网安装包内嵌、Docker/WSL2 工具链透传等）的权威需求基线。

### 1.2 背景与核心价值
在现代全栈开发中，开发者往往需要在不同的语言版本（如 Node.js 18/20/22、Python 3.10/3.12、Go、Rust、Java 等）之间频繁切换。
作为基于 Rust 构建的顶尖版本管理工具，**mise**（前身为 rtx）具备极高的执行效率。然而在 Windows 环境下，原生 CLI 交互存在诸多痛点：
1. **记忆与操作门槛高**：复杂的 CLI 参数对普通开发者不够友好，缺乏直观的多版本切换界面；
2. **Windows 环境变量配置繁复**：安装后需手工配置 `MISE_DATA_DIR`、`shims` 路径与 PowerShell Profile，极易因 PATH 顺序错乱导致版本调用失效；
3. **工具生态发现困难**：缺乏可视化的应用市场，开发者难以快速探查全网支持的 1000+ 工具与可用历史版本；
4. **升级与数据管理隐患**：传统安装方式常将工具分散在系统各个角落，重装系统或迁移数据极其困难。

Mise Manager 为 Windows 开发者提供了高度契合 Windows 11 Fluent Design 美学的可视化控制台，兼顾轻量性、零白屏秒开体验与严格的绿色目录管理。

### 1.3 术语定义
| 术语 | 英文/代号 | 详细说明 |
| --- | --- | --- |
| 统一主目录 | MISE Root Dir | 软件默认管理的运行根目录，默认为 `[应用目录]\mise`，实现绿色免污染部署 |
| 数据安装目录 | MISE_DATA_DIR | 存放所下载的各类语言 SDK、编译器与工具运行时的物理目录，对应 `mise\data` |
| 垫片执行目录 | MISE_BIN_DIR | 存放环境 Shims 代理脚本的目录，对应 `mise\data\shims`，用于命令行全局拦截与动态路由 |
| 全局激活 | Global Use | 执行 `mise use -g <tool>@<ver>`，将该版本设定为全系统命令行的默认版本 |
| 局部激活 | Local Use | 在特定项目根目录下生成 `.mise.toml`，仅在该项目工作区生效对应版本 |
| 离线市场缓存 | Market Cache | 对官方 REST API 获取的海量工具与版本数据进行本地持久化，支持离线 6 小时内毫秒级检索 |

## 2. 总体描述

### 2.1 用户画像
- **前端 / 全栈开发者**：日常维护不同时期的前端项目，需频繁切换 Node.js 16/18/20/22、pnpm、yarn 等工具链；
- **多语言开发工程师**：同时编写 Python、Go、Rust、Java 等后端应用，需要统一的环境版本调度中心；
- **Windows 11 视觉追求者**：偏好现代化原生系统美学（Fluent UI、Mica 半透明），拒绝粗糙的传统控制台界面。

### 2.2 运行环境与技术要求
- **操作系统**：Windows 10（64位） / Windows 11（推荐 64位）；
- **Node.js 运行时**：`>= 18.0.0`（生产环境打包已内嵌 Electron 32 运行时）；
- **系统底层依赖**：Windows PowerShell 5.1 或 PowerShell 7+（用于环境变量写入与 Profile 自动化配置）。

### 2.3 设计原则与约束
1. **绿色便携原则**：应用本体与下载的语言包完全解耦，支持将数据目录重定向至大容量盘符（如 `D:\developmentTool\mise`），覆盖升级不丢失任何数据；
2. **原子安全注入**：修改 Windows 系统环境变量时，严禁覆盖丢失用户原有的系统 PATH，必须执行原子差量注入与冲突路径清理；
3. **响应式与无假死**：长时间运行的 CLI 安装或编译任务必须基于子进程流式推送实时日志，界面杜绝卡死，且支持用户随时中断。

## 4. 非功能需求（NFR）

### 4.1 性能指标（Performance）
- **离线市场检索**：在本地 1000+ 工具列表中输入关键字，筛选渲染响应时间 ≤ **50 毫秒**；
- **冷启动响应**：双击启动到界面完整渲染展示（TTI） ≤ **1.2 秒**；
- **内存占用**：界面就绪且无后台下载任务时，Electron 主进程与渲染进程总内存占用 ≤ **140 MB**。

### 4.2 稳定性与鲁棒性（Reliability）
- **网络容错**：在网络不可用或 GitHub API 超时（403/404）时，应用必须优雅回退展示本地离线缓存或离线友好提示，禁止界面崩溃；
- **进程树安全管理**：用户点击“中止”时，必须调用 Windows 原生 `taskkill /pid <PID> /f /t`，确保将包含子命令行在内的所有进程树彻底强杀，杜绝残留僵尸进程。

### 4.3 兼容性（Compatibility）
- 完美兼容 64 位 Windows 10（1809 及以上）与 Windows 11；
- 兼容 Windows 自带 Windows PowerShell 5.1 以及跨平台现代 PowerShell 7。
